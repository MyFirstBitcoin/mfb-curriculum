# 9.7 Wallets are interfaces

Use the sentence:

> A [Bitcoin wallet](https://curriculum.myfirstbitcoin.org/lexicon/en/#bitcoin-wallet) manages keys and transaction information. It does not store bitcoin inside the phone or device.

Show the separation among:

* the shared Bitcoin [ledger](https://curriculum.myfirstbitcoin.org/lexicon/en/#ledger)
* the wallet's keys and signing function
* the wallet's interface and network connection; and
* any external service the wallet depends on.


<!-- micrographic: wallet-manages-keys-01 -->
[A wallet holds the keys. With them you can receive and send bitcoin, while the bitcoin itself stays recorded on the shared ledger, not inside the phone or device.](/micrographics/wallet-manages-keys-01/en.md)


Ask:

* If the phone breaks, what still exists?
* What makes access recoverable or unrecoverable?
* Does an application called a “wallet” always give the user control of the keys?

When comparing wallets, use consistent criteria:

* [custody](https://curriculum.myfirstbitcoin.org/lexicon/en/#custody)
* verified source and open-source status
* recovery and compatibility
* [privacy](https://curriculum.myfirstbitcoin.org/lexicon/en/#privacy) and server dependence
* supported payment types
* continuity and maintenance
* cost and device fit; and
* available safe support.

Prefer well-established open-source wallet software where it fits the learner's needs because publicly inspectable code can improve transparency. Treat that preference as one part of a contextual judgment, not a rule or guarantee. Every wallet has trade-offs, and open source does not prove that a tool is safe, maintained, correctly installed, or suitable for a learner. Help learners identify whether the code is publicly inspectable and compare that with custody, recovery, compatibility, privacy, cost, maintenance, and safe local support. Do not create a global approved-wallet list inside the course or present one wallet as the universal choice.
