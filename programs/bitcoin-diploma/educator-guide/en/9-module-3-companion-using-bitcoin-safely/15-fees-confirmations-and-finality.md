# 9.16 Fees, confirmations, and finality

Explain that an on-chain fee is based mainly on transaction data and demand for [block space](https://curriculum.myfirstbitcoin.org/lexicon/en/#block-space), not simply the value sent. Wallet estimates can be inaccurate or become stale.

A transaction:

* is **unconfirmed** after [broadcast](https://curriculum.myfirstbitcoin.org/lexicon/en/#broadcast) and before inclusion in a valid block
* receives its first [**confirmation**](https://curriculum.myfirstbitcoin.org/lexicon/en/#confirmation) when included in a valid block; and
* gains more settlement confidence as additional valid blocks build on that history.

[Confirmations](https://curriculum.myfirstbitcoin.org/lexicon/en/#confirmation) do not repair an incorrect destination, reverse a scam, prove the recipient's identity, or make an unwanted purchase appropriate.

There is no one [confirmation](https://curriculum.myfirstbitcoin.org/lexicon/en/#confirmation) count suitable for every value and risk. Teach the reasoning rather than a universal number.
