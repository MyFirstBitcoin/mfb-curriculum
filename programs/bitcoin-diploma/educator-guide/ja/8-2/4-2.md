# 8.4 推奨される2時間の進行案

| 時間 | 学習の流れ | 推奨される方法 |
| --- | --- | --- |
| 0〜10分 | モジュール1の振り返り | お金の問題を1つ挙げ、それが生むトレードオフを説明する |
| 10〜27分 | 分散型デジタルマネーが難しかった理由 | デジタルコピーと二重支払いのシナリオ |
| 27〜42分 | ビットコインによる複合的な解決策 | プロセスマップ：承認、ブロードキャスト、マイニング、検証、履歴の共有 |
| 42〜62分 | 役割と分散化 | ユーザー／ノード／マイナー／開発者の役割に関する課題 |
| 62〜77分 | プルーフ・オブ・ワーク | 「生成にはコストがかかり、確認はすぐにできる」ことを示すデモンストレーション |
| 77〜92分 | 供給量、半減期、サトシ | 発行モデルと単位バイアスの確認 |
| 92〜110分 | 健全な通貨（サウンドマネー）の比較 | モジュール1の特性を再利用し、利点とトレードオフを加える |
| 110〜117分 | 範囲と責任 | ビットコインとステーブルコイン／その他の資産の違い、学習と投機の違い |
| 117〜120分 | まとめと次への橋渡し | 法定通貨の課題 → ビットコインによる解決策 → 新たな責任 |
