# 10.10 Opzione A del modulo: confronto tra percorsi di pagamento locali

**Obiettivo:** Confrontare il percorso completo di un pagamento locale esistente, di un percorso on-chain e, ove opportuno, di un percorso Lightning.

**Preparazione:** Utilizzi un importo e un destinatario di pagamento inventati ma realistici. Prepari informazioni locali datate su commissioni, cambio, tempistiche, [custodia](https://curriculum.myfirstbitcoin.org/lexicon/en/#custody) e accesso. Se i dati non possono essere verificati, li indichi chiaramente come ipotetici.

**Attività del discente:** Completare:


| Campo | Metodo esistente | Bitcoin on-chain | Lightning, se pertinente |
| --- | --- | --- | --- |
| Importo inviato |  |  |  |
| Importo totale ricevuto |  |  |  |
| Tempi e aspettative di regolamento |  |  |  |
| Commissioni e spread |  |  |  |
| Custodia in ogni fase |  |  |  |
| Identità e privacy |  |  |  |
| Storno o rimborso |  |  |  |
| Principale punto di fallimento |  |  |  |
| Supporto locale o normativa |  |  |  |


**Produzione:** Il discente sceglie un percorso per il caso inventato, dimostra o mette in sequenza la relativa richiesta di pagamento e la verifica, e spiega perché l'altro percorso potrebbe essere migliore in condizioni diverse.

**Discussione finale:** Bitcoin ha migliorato il percorso completo o solo una fase visibile? Chi sostiene il rischio di volatilità, di conversione, di [custodia](https://curriculum.myfirstbitcoin.org/lexicon/en/#custody) e di fallimento?

**Sicurezza:** Non è richiesto alcun trasferimento reale né alcun fornitore specifico. Utilizzi informazioni di pagamento stampate.
